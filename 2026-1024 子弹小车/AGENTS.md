# 小车程序融合记录与维护约定

更新日期：2026-10-24

## 已确认目标

- 用户后续确认：配网成功后保留原热点和页面，自动显示灵矽激活状态与激活码，绑定成功后关闭热点；平台重试、WSS 和令牌策略继续沿用原方式。

- 以本目录的 linx-esp32 为主工程，按最小改动原则融合旁边 ESP32-S3 工程的小车业务。
- 联网、OTA 激活、令牌、协议、音频采集与 Opus 使用 linx 原实现；用户明确异常恢复、WSS 与令牌处理不迁入旧工程策略。
- 不引入 Arduino，不迁入旧 main.cpp、Inmp441、LinxClient 或 OtaGateway 的基础设施实现。
- AI 返回完整五字段纯 JSON：forward、backward、turn_left、turn_right、fire，各值为字符串 on/off。不能从识别文字、关键词、表情或 MCP 工具触发小车动作。
- 复用旧工程的受限解析器，允许乱序与 JSON 空白，拒绝缺失、重复、未知字段及非法值。非串口测试模式下，完整正常回复解析失败时输出全零状态；中断、超长或不完整回复丢弃，不扩展中断动作策略。当前串口测试模式遵循下述“格式错误后不执行”的新确认要求。
- 用户已确认兼容转向字段别名：`turn_left`/`turnleft`、`turn_right`/`turnright`，同一动作字段的不同写法仍算重复并拒绝；不扩展其他字段或值。
- bit 0～4 依次为前进、后退、左转、右转、发射/本地 LED；允许组合，bit 5～7 固定为 0。
- STM32 执行运动；ESP32 仅发送状态并控制本地低有效 LED，不新增动作互斥或运动计时。
- UART 115200，帧为 AA 55 STATE CRC8；CRC 覆盖前三字节，多项式 07、初值 00、不反射、结果异或 00。必须发送合法全零状态，不添加周期状态心跳。
- UART TX/RX 与 LED GPIO 未确定，不代选或启用实际引脚；通过配置逐项启用，默认仅解析和记录状态。
- 持续监听采用已有 AutoStop 会话循环：激活后自动开启会话，正常回复后继续监听；回复期间暂停上传，不自行启用 Realtime/AEC，也不增加断线自动恢复策略。

## 实现边界

- 小车逻辑放在 main/car/；application 仅提供必要事件接入，全部业务状态在应用主任务中更新。
- 异步回调必须复制 cJSON 字符串，不保留网络回调结束后失效的指针。
- 以 tts.start 开始、sentence_start 追加、tts.stop 结束汇总；仅明确 is_aborted=false 且未被本地取消的完整回复可执行。重复开始不能清空本轮已收集文字，重复结束不能重复执行。
- 接入断线/错误时只丢弃未完成文字，不新增断网停机、三次重试或令牌处理。
- 保留 linx 原音频基础设施；小车模式默认忽略服务端下行语音，避免播读控制 JSON，系统提示音保持原行为。MAX98357 是否用于其他播放留待确认。
- 保留当前 PlatformIO 面包板编译配置；真实麦克风、屏幕、按键接线尚未验证。启用 UART/业务 LED 时必须核对它们与板级 I²S、显示、按键、状态灯及示例灯的 GPIO 不冲突。
- 不修改其他板型的既有行为；通过 CAR_CONTROL 配置隔离融合逻辑。

## 配网页激活码（2026-10-24）

- 已实现成功页显示与复制激活码，自动刷新连接/等待/错误/成功状态；不用依赖扬声器读码。
- 配网后保留 AP，原 WifiStation 使用 AP+STA 模式连接路由器；激活成功后只关闭 AP/网页并保留 STA，不新增重连流程。
- 以原 ShowActivationCode 入口发布激活码；真正取得平台连接配置且无需继续激活后，才显示成功。激活码和提示仅存内存，不暴露密码、token 或 OTA 原始数据。
- 原配网组件本地维护于 third_party/esp-wifi-connect，源版本 3.0.2，main/idf_component.yml 通过 override_path 引用；不可将变更仅写到 managed_components。
- CONFIG_WIFI_ACTIVATION_PORTAL 默认为关闭，当前 PlatformIO defaults 启用。已有 Wi-Fi 的普通启动不主动开热点，跨重启热点恢复不在本轮扩展。
- 页面成功后请求退出，设备另有 5 秒自动关闭兜底；关闭任务通过配网代际约束，避免影响新一轮热点。
- 页面 4 组测试与原小车 8 组测试通过，已检查模拟激活码下的手机宽度布局；最终固件构建成功，实际启用 CONFIG_WIFI_ACTIVATION_PORTAL。静态 RAM 69,092 字节（21.1%），程序占应用分区 2,622,679 字节（63.5%），已生成新的 firmware.bin。
- 尚未实机验证 AP+STA、手机页面持续访问、平台实际返回激活码/绑定、成功后 STA 连续联网。详情见 docs/wifi-activation.md。

## 串口文字测试（2026-10-24）

- 用户已确认：电脑串口助手发送一句文字，AI 回复显示在串口；按现有控制台、115200、UTF-8、逐行发送方案实现。
- `CONFIG_SERIAL_TEXT_CHAT` 默认为关闭，当前 PlatformIO 配置启用；启用时覆盖原有自动监听设置，禁止麦克风上传、唤醒、小车 UART/业务 LED 初始化及回复动作执行。关闭配置恢复原语音与小车路径。
- 复用已配置的 UART 与 USB Serial/JTAG 控制台，不指定新 GPIO，不占用 STM32 业务 UART。两个端口分别组帧，最多 1024 字节；拒绝非法 UTF-8/控制字符，超长整行丢弃。
- 一次一条请求，忙时拒绝，不排队、不自动重传，不新增无响应超时。网络回调复制字符串，所有平台请求和回复状态在主任务处理。
- 文字经 cJSON 序列化，通过现有 listen/detect 入口发送；平台实际是否支持任意文字、是否返回完整 tts 事件待实机验证，不能把传输成功当成 AI 接受成功。

- 软件检查：新增串口输入 5 组与原小车 8 组测试全部通过；实际文字协议发送函数的 JSON 转义/字段注入/失败返回检查通过；关闭模式的 application.cc 编译检查通过。真实设备收发与平台入口仍待联调。
